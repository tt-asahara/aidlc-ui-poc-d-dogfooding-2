## 前提

このアプリの使われ方は、次のとおりです。

- 依頼者が1人で、自分のパソコンのブラウザで使う。
- 公開しない。データは架空のものだけで、ブラウザの保存領域にだけ置く。
- 利用者の認証、利用者ごとの権限、サーバーはない。認証と権限の要件は対象外（範囲外。要件の「範囲外」）。

守るものは、次の3つです。

1. 依頼者のパソコンから外にデータが出ないこと
2. 利用者が入力した文字や保存データが、命令として実行されないこと
3. 保存データが壊れたり消えたりしないこと

## 脅威の見立て

| 脅威 | 起こり方 | 影響 | 対策の要件 |
|------|----------|------|------------|
| 外部への送信 | 外部のフォント・スクリプト・解析ツールを読み込む。部品が勝手に通信する | データが外に出る、NFR3 違反 | NFR3.1〜NFR3.4 |
| 文字の命令としての実行 | メモに `<script>` などを入れ、画面が HTML として扱う | 画面で任意の処理が動く | NFR4.1、NFR4.2 |
| 表計算での数式の実行 | 出力した CSV のメモが `=` で始まる | 表計算ソフトで数式が動く | U4 で対策する（数式対策、FR6.4）。U1 の CSV 出力には数式対策がないため、U4 までの CSV は試作用とする |
| 保存データの改ざん・破損 | 開発者の道具などで保存領域を書き換える | 読み込みで画面が壊れる、データが消える | NFR4.3、NFR5.3 |
| 部品の弱点 | npm の部品に既知の弱点がある | 開発の道具やアプリが攻撃される | NFR4.4 |
| 2つのタブの同時保存 | 古いタブが上書きする | 明細が消える | NFR5.4（隙間の扱いは U5） |

## 外部への通信をしない（NFR3）

| ID | 要件 | 合否の基準 | 確かめ方 |
|----|------|------------|----------|
| NFR3.1 | ビルドしたページに Content-Security-Policy を入れ、読み込みと通信を自分のファイル（同じ配信元）だけに限る。通信の先（connect-src）は許可しない | 外部のスクリプト・スタイル・フォント・画像・通信をブラウザが止める | ページの指定を確かめる単体テストと、外部の読み込みを試すブラウザ操作のテストで、止められることを確かめる |
| NFR3.2 | 外部のフォント・スクリプト・解析ツールを使わない。文字の書体は、パソコンに入っているものを使う | ビルドの出力に外部の URL がない | ビルドの出力に `http://`・`https://` で始まる読み込み先がないことを確かめる |
| NFR3.3 | アプリを使っている間、外部への通信が1件もない | Playwright で記録した通信がすべて同じ配信元 | 登録 → 集計 → CSV 出力の間の通信を記録して確かめる |
| NFR3.4 | 扱うデータは架空のものだけ。テストのデータにも、実在の人物・口座・店舗の名前を使わない | テストのデータに実在の固有名詞がない | テストのデータを見直す（コードの確認） |

Content-Security-Policy は、ビルドしたページ（依頼者が使うもの、ブラウザ操作のテストで動かすもの）に入れます。開発中の起動では、変更をすぐ画面に反映する仕組みが手元の通信を使うため、同じ指定は入れません。外部への通信がないことは、ビルドしたページで確かめます。

## 文字と保存データの扱い（NFR4）

| ID | 要件 | 合否の基準 | 確かめ方 |
|----|------|------------|----------|
| NFR4.1 | メモなど利用者が入力した文字は、常に文字として表示する。HTML として差し込む書き方（React の `dangerouslySetInnerHTML` など）は使わない | `<b>太字</b>` が文字のまま表示される。差し込む書き方がコードにない | Testing Library のテストと、ESLint の規則（差し込む書き方を禁止する規則）で確かめる |
| NFR4.2 | CSV の出力では、メモをそのまま文字として出し、カンマ・ダブルクォートを含む値は囲む | 出力の中身が形式どおり | 単体テスト（BR3.3） |
| NFR4.3 | 保存データは、読み込むときに信用しないものとして扱う。JSON として読めない、または版が 1 でないときは使わない（U1 の最小限の検出）。項目の欠けや型の誤りの検出は U5 | 壊れた保存データで画面が壊れず、読めないことが表示される | ブラウザ操作のテスト（AC7.3.3 の U1 分） |
| NFR4.4 | アプリが動くときに読み込む部品は React だけにする。npm の部品を取得したときの弱点の検査（npm audit）で、重大（critical・high）なものを残さない | 検査の結果で critical・high が 0 件 | 部品を足したときに検査する。残る場合は理由を記録して依頼者に知らせる |
| NFR4.5 | 秘密情報（鍵・パスワード）を扱わず、コードにも入れない | コードに秘密情報がない | コミット前の確認（team-practices.md） |

## 信頼性（NFR5）

| ID | 要件 | 合否の基準 | 確かめ方 |
|----|------|------------|----------|
| NFR5.1 | 保存は、明細と予算をまとめた保存データ全体を1回で書く。一部だけが書かれた状態を作らない | 保存領域の中身が、いつも完全な保存データか、保存前のまま | 単体テスト（BR4.1） |
| NFR5.2 | 保存に失敗したとき、画面で読み込んでいる内容も保存領域の中身も変えない。入力は残す | 失敗の前後で保存データが同じ | 書き込みを失敗させた単体テストとブラウザ操作のテスト（AC7.3.1） |
| NFR5.3 | 読めない保存データは、自動で消したり上書きしたりしない | 読めない保存データが、開き直してもそのまま残る | ブラウザ操作のテスト（BR4.2、BR4.6） |
| NFR5.4 | 保存の直前に通し番号を照合し、別のタブが先に保存していたら上書きしない | 古いタブからの保存が断られる | 単体テスト（BR4.4）。読み込みと書き込みの間の隙間は U5 で扱う（契約レビュー R-03） |
