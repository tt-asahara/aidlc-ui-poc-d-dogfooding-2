## 1. 登録

### US1.1 収支を登録する ★

私は家計を試す本人として、収入と支出を1件ずつ登録したい。それは、自分のお金の出入りを記録して月ごとに振り返れるようにするためだ。

- **AC1.1.1**: Given 登録フォームが表示されている、When 区分「支出」・日付「2026-10-14」・金額「1280」・カテゴリ「食費」・メモ「スーパー」を入力して「登録する」を押す、Then 明細が1件増え、「登録しました 10月14日 食費 ¥1,280」の知らせが読み上げ機能にも伝わる形で表示される。
- **AC1.1.2**: Given 区分を「収入」にした、When カテゴリの選択肢を開く、Then 「給与」「副収入」「その他収入」だけが表示される（支出は「食費」「住居費」「水道光熱費」「通信費」「日用品」「交通費」「娯楽」「その他支出」の8つ）。
- **AC1.1.3**: Given 支出カテゴリ「食費」を選んでいる、When 区分を「収入」に切り替える、Then カテゴリの選択が解除され、収入カテゴリから選び直すよう求められる。
- **AC1.1.4**: Given 正しい内容を入力した、When 「登録する」を 300 ミリ秒以内に2回押す、Then 明細は1件だけ増える。
- **AC1.1.5**: Given メモに「<b>太字</b>」と入力した、When 登録して一覧を見る、Then メモは「<b>太字</b>」という文字のまま表示され、太字にはならない。
- **AC1.1.6**: Given 一覧に明細がある、When 明細の行を見る、Then 修正・削除の操作は表示されない。
- INVEST: 単独で価値があり（1件を記録できる）、テスト可能。カテゴリは固定のため、別ストーリーにしない。

### US1.2 入力の誤りに気づいて直す

私は家計を試す本人として、入力の誤りをその場で知りたい。それは、間違った金額や日付を記録しないためだ。

- **AC1.2.1**: Given 金額に「0」「-500」「12.5」「10000000」「1,28o」のいずれかを入れた、When 「登録する」を押す、Then 登録されず、金額欄の下に「金額は 1〜9,999,999 の整数で入力してください。例: 1280」と表示され、入力した値は残る。
- **AC1.2.2**: Given 金額「9999999」、When 登録する、Then 登録できる（上限ちょうど）。金額「1」も登録できる（下限ちょうど）。
- **AC1.2.3**: Given 日付が空欄、または「2026-02-30」のように存在しない日付、When 「登録する」を押す、Then 登録されず、日付欄に理由が表示される。「2000-01-01」「2030-12-31」は登録できる。
- **AC1.2.4**: Given メモ欄、When 101 文字目を入力しようとする、Then 100 文字を超えて入力できず、欄の下に「メモは 100 文字までです」と表示される。文字数は画面に見える1文字を1文字として数える（絵文字1つは1文字）。メモは1行で、改行は入力できない。
- **AC1.2.5**: Given 誤りの表示が出ている、When その欄を直して「登録する」を押す、Then 誤りの表示が消えて登録される。
- 補足: AC1.2.4 は、要件分析レビューの R-05（FR1.5 の挙動を1つに決める）を受けて、入力させない方式に決めた。メモ 100 文字は要件の仮定 A1 のまま。

### US1.3 別の月の日付で登録する

私は家計を試す本人として、前の月に記録し忘れた支出を、今の月を見ている途中でも登録したい。それは、記録漏れを後から埋められるようにするためだ。

- **AC1.3.1**: Given 2026年10月を表示している、When 日付「2026-09-28」の明細を登録する、Then 表示が2026年9月に切り替わり、一覧と月次集計に登録した明細が反映され、「9月の明細として登録しました」と知らせる。
- **AC1.3.2**: Given 2026年10月を表示している、When 日付「2026-10-05」の明細を登録する、Then 表示月は10月のまま変わらない。
- 出典: Q2（要件分析レビュー R-01）。

## 2. 一覧

### US2.1 月の明細を一覧で見る

私は家計を試す本人として、その月に何を登録したかを一覧で見たい。それは、記録の抜けや重複に気づくためだ。

- **AC2.1.1**: Given 10月に明細が3件ある（10/1、10/5、10/5）、When 10月を表示する、Then 日付の新しい順に並び、同じ10/5の2件は後から登録した方が上になる。
- **AC2.1.2**: Given CSV の取り込みで同じ日付の行が複数追加された、When 一覧を見る、Then 同じ日付の中では、ファイルの下の行ほど上に表示される（後から追加したものが上という規則と同じ）。
- **AC2.1.3**: Given 金額 12800 の支出、When 一覧を見る、Then 「−¥12,800」と右揃えで表示される。収入は「+」を付ける。
- **AC2.1.4**: Given 明細のない月、When その月を表示する、Then 空の表ではなく「この月の明細はまだありません。上のフォームから登録するか、CSV を取り込むと、ここに表示されます。」と表示される。
- 補足: AC2.1.2 は要件分析レビュー R-05（取り込み行の同日の順序）を受けて決めた。

## 3. 月次集計

### US3.1 月の収支を確認する ★

私は家計を試す本人として、その月の収入合計・支出合計・差額を見たい。それは、月の収支がプラスかマイナスかをすぐに知るためだ。

- **AC3.1.1**: Given 10月の収入 ¥280,000・支出 ¥119,220 の明細がある、When 10月の月次集計を見る、Then 収入 ¥280,000、支出 ¥119,220、差額 ¥160,780 と表示される。
- **AC3.1.2**: Given 支出が収入より多い月、When 月次集計を見る、Then 差額に「−」が付いて表示される。
- **AC3.1.3**: Given 2026年1月を表示している、When 「前の月」を押す、Then 2025年12月が表示される。「次の月」で2026年1月に戻る。
- **AC3.1.4**: Given アプリを開いた日が2026年10月16日、When 開く、Then 2026年10月が表示される。
- **AC3.1.5**: Given 任意の明細、When 月次集計を見る、Then 支出カテゴリ別実績の合計は支出合計と一致する。
- **AC3.1.6**: Given 9,999,999 円の支出を 300 件登録した月、When 月次集計を見る、Then 支出合計は ¥2,999,999,700 と正しく表示される（端数や誤差がない）。

### US3.2 カテゴリ別に予算と実績を比べる

私は家計を試す本人として、支出カテゴリごとに予算・実績・残額を見たい。それは、使いすぎているカテゴリに早く気づくためだ。

- **AC3.2.1**: Given 10月の食費の予算 ¥40,000、実績 ¥9,570、When 月次集計を見る、Then 食費の行に 予算 ¥40,000、実績 ¥9,570、残額 ¥30,430 と表示される。
- **AC3.2.2**: Given 食費の予算 ¥40,000、実績 ¥43,900、When 月次集計を見る、Then 残額欄に「超過 ¥3,900」と文字で表示され、色でも区別される。
- **AC3.2.3**: Given 娯楽に10月の予算が設定されていない、実績 ¥12,800、When 月次集計を見る、Then 予算欄は「未設定」、残額欄は「—」と表示され、超過表示にはならない。
- **AC3.2.4**: Given 収入カテゴリ、When 月次集計を見る、Then 予算・残額の欄はなく、収入は合計にだけ含まれる（予算は支出カテゴリのみ。要件の仮定 A3）。

## 4. 予算

### US4.1 月の予算を入力する

私は家計を試す本人として、月ごと・支出カテゴリごとに予算を決めたい。それは、その月の使いすぎを判断する基準にするためだ。

- **AC4.1.1**: Given 10月の月次集計の表、When 食費の予算欄に「40000」を入れて保存する、Then 食費の予算が ¥40,000 になり、残額が更新される。9月・11月の食費の予算は変わらない。
- **AC4.1.2**: Given 予算欄、When 「-1」「1.5」「10000000」を入れて保存する、Then 保存されず、その欄に「予算は 0〜9,999,999 の整数で入力してください」と表示され、入力した値は残る。「0」は保存できる。
- **AC4.1.3**: Given 食費の予算が ¥40,000、When 予算欄を空にして保存する、Then 食費の予算は「未設定」に戻る。

### US4.2 前の月の予算をコピーする

私は家計を試す本人として、前の月の予算をまとめて写したい。それは、毎月同じ予算を入力し直す手間を省くためだ。

- **AC4.2.1**: Given 9月に食費 ¥40,000・住居費 ¥82,000 の予算があり、10月には予算がない、When 10月で「前の月の予算をコピー」を押す、Then 10月の食費と住居費に同じ額が入る。
- **AC4.2.2**: Given 10月にすでに予算が1つ以上ある、When 「前の月の予算をコピー」を押す、Then 「10月の予算を前の月の内容で上書きします」と確認が出て、「上書きする」なら写し、「やめる」なら何も変わらない。
- **AC4.2.3**: Given 9月に予算が1つもない、When 10月で「前の月の予算をコピー」を押す、Then 「前の月の予算がありません」と表示され、10月の予算は変わらない。

## 5. CSV 出力

### US5.1 明細を CSV に保存する ★

私は家計を試す本人として、すべての明細を CSV ファイルに保存したい。それは、表計算ソフトで見たり、ブラウザのデータが消えたときの控えにしたりするためだ。

- **AC5.1.1**: Given 明細が 10 件ある、When 「明細を CSV に保存」を押す、Then `budget-entries-YYYYMMDD.csv`（保存した日の日付）がダウンロードされ、見出し1行と10行のデータが日付の古い順に入っている。
- **AC5.1.2**: Given 出力したファイル、When 中身を確かめる、Then 文字コードは UTF-8（BOM 付き）、改行は CRLF、見出しは「日付,区分,カテゴリ,金額,メモ」、日付は YYYY-MM-DD、金額は区切りなしの整数である。
- **AC5.1.3**: Given メモが「ランチ, 2人分」「"特売"」「改行なし」の明細、When 出力して同じファイルを取り込み直す（重複確認で「すべて追加」を選ぶ）、Then 追加された明細のメモは元と完全に同じになる。
- **AC5.1.4**: Given 明細が 0 件、When 「明細を CSV に保存」を押す、Then ファイルは作られず、「出力する明細がありません」と表示される。
- **AC5.1.5**: Given CSV 出力の説明文、When 画面を見る、Then 「CSV には明細だけが含まれ、予算は含まれません」と書かれている。
- 補足: AC5.1.5 は Q6（要件分析レビュー R-07）による。

### US5.2 数式のようなメモを安全に出力する

私は家計を試す本人として、出力した CSV を表計算ソフトで開いても、メモが数式として実行されないようにしたい。それは、意図しない計算や命令が動くのを防ぐためだ。

- **AC5.2.1**: Given メモが「=1+1」「+81」「-5」「@sum」「'=x」、またはタブや改行で始まる明細、When CSV に出力する、Then そのメモの値の先頭に「'」が1つ付く（例:「'=1+1」「''=x」）。
- **AC5.2.2**: Given AC5.2.1 で出力したファイル、When 取り込む、Then 先頭の「'」が1つだけ外れ、メモは元と完全に同じ（「=1+1」「'=x」など）になる。
- **AC5.2.3**: Given メモが「スーパー」のように該当しない明細、When 出力する、Then 「'」は付かない。
- 出典: Q3（要件分析レビュー R-02）。要件 FR6.4 の規則を、往復で元に戻るこの規則に置き換える。

## 6. CSV 取り込み

### US6.1 CSV を取り込んで明細を追加する

私は家計を試す本人として、CSV ファイルの明細をまとめて追加したい。それは、控えから戻したり、架空データをまとめて入れたりするためだ。

- **AC6.1.1**: Given 既存の明細が 5 件、正しい 12 行の CSV、When 取り込む（重複なし）、Then 明細は 17 件になり、既存の 5 件は残り、「12件の明細を追加しました」と表示される。
- **AC6.1.2**: Given BOM なし・改行 LF の CSV、When 取り込む、Then BOM 付き・CRLF と同じく正しく取り込める。
- **AC6.1.3**: Given 1行目が「date,type,category,amount,memo」の CSV、When 取り込む、Then 何も追加されず、「1行目は『日付,区分,カテゴリ,金額,メモ』である必要があります」と表示される。
- **AC6.1.4**: Given 見出しだけの CSV、When 取り込む、Then 「取り込む明細がありません」と表示され、何も追加されない。
- **AC6.1.5**: Given 6 MB のファイル、または 10,001 行のデータ行がある CSV、When 取り込む、Then 取り込みは始まらず、「1回に取り込めるのは 5 MB・10,000 行までです」と表示される。
- **AC6.1.6**: Given 取り込みの途中で保存に失敗する、When 取り込む、Then 明細は取り込み前の件数のまま変わらず、失敗したことが表示される。
- **AC6.1.7**: Given 取り込み後の表示、When 件数を確かめる、Then 「追加」「取り込めなかった」「重複として除いた」の件数の合計が、ファイルのデータ行数（空行を除く）と一致する。

### US6.2 取り込めない行を知る

私は家計を試す本人として、CSV のどの行がなぜ取り込めなかったかを知りたい。それは、ファイルを直して取り込み直せるようにするためだ。

- **AC6.2.1**: Given 3行目の金額が「abc」、7行目のカテゴリが「ペット」、ほかは正しい 10 行の CSV、When 取り込む、Then 正しい 8 行が追加され、「3行目: 金額が数字ではありません」「7行目: カテゴリ『ペット』は用意されていません」と表示される。
- **AC6.2.2**: Given 日付が「2026/10/1」、金額が「1,280」や全角の「１２８０」の行、When 取り込む、Then その行は取り込まれず、日付は YYYY-MM-DD、金額は半角数字で書くよう理由が表示される。
- **AC6.2.3**: Given 値の前後に空白がある行（例:「 食費 」「 1280 」）、When 取り込む、Then 空白を除いて正しく取り込まれる。
- **AC6.2.4**: Given 列が 5 つでない行、When 取り込む、Then その行だけ取り込まれず、「4行目: 列の数が 5 つではありません」と表示される。
- **AC6.2.5**: Given 途中や末尾に空行がある CSV、When 取り込む、Then 空行は無視され、件数にも数えない。
- **AC6.2.6**: Given 閉じていないダブルクォートがある、または UTF-8 として読めない（Shift_JIS など）ファイル、When 取り込む、Then 取り込みを始めず、ファイル全体を取り込めない理由（「UTF-8 で保存したファイルを選んでください」など）を表示する。
- **AC6.2.7**: Given 区分が「支出」でカテゴリが「給与」の行、When 取り込む、Then その行は取り込まれず、区分とカテゴリが合わないと表示される。
- 出典: Q4（要件分析レビュー R-03）、要件 FR7.4、FR7.5。

### US6.3 重複した取り込みを避ける

私は家計を試す本人として、同じ明細を二重に取り込みそうなときに知りたい。それは、明細を削除できないため、集計が二重になるのを防ぐためだ。

- **AC6.3.1**: Given すでに取り込んだ CSV、When 同じファイルをもう一度取り込む、Then 追加する前に「既存と同じ明細が N 件あります」と表示され、「重複分を除いて追加」「すべて追加」「取り込みをやめる」から選べる。
- **AC6.3.2**: Given 重複の確認で「重複分を除いて追加」を選ぶ、When 取り込みが終わる、Then 既存と同じ明細は追加されず、除いた件数が表示される。
- **AC6.3.3**: Given 重複の確認で「取り込みをやめる」を選ぶ、When 確認を閉じる、Then 明細は1件も増えない。
- **AC6.3.4**: Given 1つのファイルの中に同じ内容の行が2行ある（既存の明細とは重複しない）、When 取り込む、Then 2行とも追加される（重複の確認は既存の明細とだけ比べる。要件の仮定 A10）。
- **AC6.3.5**: Given 既存の明細と日付・区分・カテゴリ・金額は同じでメモだけ違う行、When 取り込む、Then 重複とは数えない。

## 7. 初回と保存

### US7.1 サンプルデータで試し始める

私は家計を試す本人として、初めて開いたときから架空のデータで画面を試したい。それは、何も入力しなくても集計や予算の表示を確かめられるようにするためだ。

- **AC7.1.1**: Given このブラウザで初めて開く（保存データがない）、When アプリを開く、Then 今月を含む直近3か月分の架空の明細と予算が入っている。
- **AC7.1.2**: Given サンプルデータ、When 3か月分の月次集計を順に見る、Then 少なくとも1つの月で「超過」表示と「未設定」表示がそれぞれ見られる。
- **AC7.1.3**: Given 2回目以降に開く、When アプリを開く、Then サンプルは追加されず、前回までのデータがそのまま表示される。
- **AC7.1.4**: Given サンプルデータのメモ、When 内容を見る、Then 実在の人物・口座・店舗名は含まれない。

### US7.2 開き直してもデータが残る ★

私は家計を試す本人として、ブラウザを閉じて開き直しても記録が残っていてほしい。それは、試作を何日かに分けて使えるようにするためだ。

- **AC7.2.1**: Given 明細を1件登録し、10月の食費の予算を ¥40,000 にした、When ブラウザを閉じて同じパソコン・同じブラウザで開き直す、Then その明細と予算が表示される。

### US7.3 保存できないときに気づく

私は家計を試す本人として、データが保存できなかったときや、保存データが壊れているときにそれを知りたい。それは、登録したつもりでデータを失うことを防ぐためだ。

- **AC7.3.1**: Given ブラウザに保存できない状態、When 明細を登録する、Then 「このブラウザに保存できませんでした」と、入力が画面に残っていること・再試行の方法が表示され、入力値は残る。「登録しました」とは表示されない。
- **AC7.3.2**: Given ブラウザに保存できない状態、When 予算を保存する、または CSV を取り込む、Then AC7.3.1 と同じく失敗が表示され、成功の表示は出ない。
- **AC7.3.3**: Given 保存データが壊れていて読み込めない、When アプリを開く、Then 「保存データを読み込めませんでした。データは消していません」と表示され、登録・予算保存・取り込みの操作は止まり（押せない状態で理由が分かる）、サンプルデータは入れ直されない。
- **AC7.3.4**: Given AC7.3.3 の状態、When 何も操作せずに閉じて開き直す、Then 壊れた保存データはそのまま残っている（上書き・消去されていない）。
- 出典: Q5（要件分析レビュー R-04）、要件 FR9.2、FR9.3。

### US7.4 2つのタブで食い違わない

私は家計を試す本人として、うっかり2つのタブで開いていても、片方の変更をもう片方で消してしまわないようにしたい。それは、登録した内容が知らないうちに失われるのを防ぐためだ。

- **AC7.4.1**: Given 同じブラウザでアプリを2つのタブで開いている、When タブ1で明細を登録する、Then タブ2に「別のタブで変更がありました。最新の内容を読み込みました」と表示され、タブ2の一覧と集計にもその明細が出る。
- **AC7.4.2**: Given AC7.4.1 のあと、When タブ2で明細を登録する、Then タブ1で登録した明細も消えずに残っている。
- 出典: Q5（要件分析レビュー R-04）。

## 8. 全体の使いやすさ

### US8.1 キーボードだけで一連の操作を終える

私は家計を試す本人として、マウスを使わなくても成功基準の操作を最後まで行いたい。それは、誰でも使える画面であることを確かめるためだ。

- **AC8.1.1**: Given アプリを開いた直後、When キーボードの Tab キーを押す、Then 最初に「本文へ移動」が選ばれ、それを使うと登録フォームの先頭へ移動する。
- **AC8.1.2**: Given キーボードだけを使う、When 登録 → 月次集計を確認 → CSV に出力を行う、Then マウスを使わずに最後まで完了でき、操作中の場所が常に枠線で見える。
- **AC8.1.3**: Given 自動のアクセシビリティ検査（axe）、When 主要な画面の状態（通常・入力誤り・取り込み結果）を検査する、Then 重大（critical・serious）な違反が 0 件である。
- **AC8.1.4**: Given 依頼者が初めてアプリを使う、When 手順書なしで登録 → 月次集計を確認 → CSV に出力を行う、Then 誰の助けも借りずに 5 分以内に3つとも完了できる。
- 出典: 要件 NFR2、NFR8。AC8.1.3 と AC8.1.4 は、要件分析レビュー R-06（判定基準が弱い）を受けて具体化した。axe の採用と 5 分の目安は、ここで置いた仮定（依頼者の確認待ち）。
