# 画面部品の設計 — U1 薄い版

画面の構成は詳細モックアップ（`aidlc/spaces/default/intents/261016-budget-manager-app/inception/refined-mockups/mockups.md`、`interaction-spec.md`）の案A です。1画面に、上から「1 登録」「2 確認」「3 書き出し」を縦に並べます。動きの手順と状態の移り変わりは `functional-spec.md`、規則は `rules.md` にあります。

画面部品は、計算も保存もしません（ADR-004）。計算は MonthlySummary、保存は DataStore、明細の規則は Ledger が受け持ちます。

## 部品の階層

```
AppShell（起動、今日、表示中の月、組み立て、差し込み口の差し替え）
├─ 見出し「予算管理  架空データで試す家計簿」
├─ 本文へ移動（登録フォームの先頭へ）
├─ [全体のお知らせ枠の置き場所]（U5 の NoticeBannerView。U1 では空）
├─ EntryFormView「1 登録」
│   ├─ お知らせ枠（成功は status、失敗は alert）
│   ├─ 区分（ラジオボタン2つ、fieldset と legend）
│   ├─ 日付・金額（円）
│   ├─ カテゴリ（区分に合うものだけ）
│   ├─ メモ（任意、100 文字まで）
│   └─ 「登録する」
├─ ReviewView「2 確認」
│   ├─ 月の切り替え（「前の月」・月名・「次の月」）
│   ├─ 収入・支出・差額
│   └─ 支出カテゴリ別の表（カテゴリ・予算・実績・残額）
│       ［明細の一覧の置き場所（U2）、予算の保存とコピーの置き場所（U3）］
└─ ExportView「3 書き出し」
    ├─ お知らせ枠
    ├─ 説明（追加のみ・予算は含まれない・形式）
    ├─ 「明細を CSV に保存」
    └─ ［取り込みの置き場所（U4）］
```

あとの Unit が足す部分には、置き場所だけを決めておきます。U1 では何も表示しません。

## 部品ごとの受け取るものと持つ状態

| 部品 | 受け取るもの | 自分で持つ状態 | 呼ぶもの |
|------|--------------|----------------|----------|
| AppShell | なし | AppState（表示中の月、storeStatus、lastExternalChangeAt）、今日 | DataStore.load、サンプル投入の差し込み口、各画面部品の組み立て |
| EntryFormView | AppState（storeStatus）、今日、カテゴリの一覧 | 入力中の値、フォームの状態（default・submitting・success・invalid・storageError・disabled）、お知らせの文 | Ledger.add |
| ReviewView | AppState（表示中の月、storeStatus）、保存の知らせ | なし（表示のたびに集計を読み直す） | MonthlySummary.summarize、AppShell.selectMonth |
| ExportView | AppState（storeStatus）、今日、保存の知らせ | お知らせの文（明細の件数は持たない。0件の判定は exportAll が行う） | CsvExchange.exportAll |

storeStatus が unreadable のときは、3つの区切りのそれぞれで、読めないことを伝えます（BR4.2、BR4.6）。

| 区切り | 表示 |
|--------|------|
| 登録 | 「登録する」を押せない状態にし、理由を出す |
| 集計 | ¥0 の集計の代わりに理由を出す |
| CSV | 「明細を CSV に保存」を押せない状態にし、理由を出す |

保存の知らせ（committed・externalChange・unreadable）は、AppShell が DataStore から受け取って AppState を更新し、画面部品へ伝えます。ReviewView と ExportView は、どの知らせでも同じように読み直します（`functional-spec.md` の「保存の知らせ」）。

## 入力と検証（U1 の分）

| 項目 | 初期値 | U1 で確かめること | U2 で足すこと |
|------|--------|------------------|---------------|
| 区分 | 支出 | 必須（BR1.1） | なし |
| 日付 | 今日 | 必須（BR1.1）。日付の入力欄を使う | 存在しない日付の理由表示 |
| 金額（円） | 空 | 必須、1〜9,999,999 の半角の整数（BR1.1、BR1.2） | 欄の下の直し方の表示 |
| カテゴリ | 空 | 必須、区分に合うもの（BR1.1、BR1.3） | なし |
| メモ | 空 | 前後の空白を除く。入力欄の上限 100 文字、改行不可（BR1.4） | 見える1文字で数える |

誤りがあれば、お知らせ枠に「入力を確かめてください: 」に続けて直す欄の名前を出し、最初の誤りの欄へ操作位置を移します（Q4）。

## アクセシビリティ（U1 で作り込む基本）

`interaction-spec.md` と `accessibility-checklist.md` のうち、U1 の部品に当たるものを作り込みます。

- 最初の Tab で「本文へ移動」が選ばれ、登録フォームの先頭へ移動する。
- 各欄に見える見出し（label）を付ける。区分は fieldset と legend。
- 操作位置に 3px の枠線を表示する。
- 成功のお知らせは role=status（polite）、失敗は role=alert で読み上げる。
- 月名は aria-live="polite" で読み上げる。ボタンは「前の月」「次の月」の文字を表示する。
- 集計の表は table と caption を使い、列見出しと行見出しを付ける。
- 状態は色だけで伝えない。
- 本文のコントラスト比は 4.5:1 以上にする。

通しのキーボード操作の確認と axe の検査は、U6 でまとめて行います。U1 のブラウザ操作のテストでも、登録 → 集計 → CSV 出力をキーボードだけで行えることは確かめます。
