# 部品間の約束ごとの設計 — 質問

Unit（`aidlc/spaces/default/intents/261016-budget-manager-app/inception/units-generation/unit-of-work.md`）は、すべて1つの Web アプリの中で動きます。そのため約束ごとは、ネットワーク越しの API ではなく、アプリ内の部品の呼び出し方とデータの形になります。外部に公開する API はありません（外部送信なし。要件 NFR3）。

ここで約束ごとを先に決めておくと、U2〜U5 を並行して作っても組み合わせたときに食い違いません。これまでのレビューで残った次の点も、ここで解消します。

- 保存データの形
- 保存失敗の返し方
- 古いタブからの書き込み
- 状態を画面へ伝える方法

どの質問も A がおすすめです。

## Q3. 古い内容を表示したままのタブから保存しようとしたら、どうしますか？

ドメイン設計のレビューで指摘された点です。何もしないと、別のタブで登録した明細が消えます。

A. 保存のたびに通し番号を照合し、別のタブが先に保存していたら保存を断る。最新の内容を読み直して「別のタブで変更があったため保存できませんでした。もう一度操作してください」と知らせ、入力は残す（おすすめ）
B. 後から保存した方で上書きする（別のタブの変更は消える）
C. 特に希望はない（おすすめでよい）
