# 予算管理（架空データで試す家計簿）

収入と支出を登録し、月ごとの収支を確かめ、明細を CSV に保存できる Web アプリです。
ブラウザの中だけで動き、データはそのブラウザの保存領域（localStorage）にだけ置きます。外部への送信はしません。
扱うデータは架空のものだけにしてください。

この版（U1 薄い版）でできること:

- 収支を1件ずつ登録する（区分・日付・金額・カテゴリ・メモ）
- 月ごとの収入・支出・差額と、支出カテゴリ別の実績を見る（「前の月」「次の月」で切り替え）
- すべての明細を CSV ファイルに保存する
- ブラウザを閉じて開き直しても、登録した明細が残る

## 必要なもの

- Node.js 24（版は `.nvmrc` にあります）と npm

## 起動の手順

すべて `app/` の中で実行します。

1. 初回だけ、部品を取得します（`package-lock.json` の版で取得します）。

   ```bash
   npm ci
   ```

2. ビルドします。

   ```bash
   npm run build
   ```

3. 手元の配信を始めます。

   ```bash
   npm run serve
   ```

4. ブラウザで <http://127.0.0.1:4173/> を開きます。

5. 終えるときは、`npm run serve` を Ctrl+C で止めます。保存データはブラウザに残ります。

保存データはページの配信元（`http://127.0.0.1:4173`）ごとに分かれます。毎回同じアドレスで開いてください。
ポート 4173 が使われていると、`npm run serve` は別のポートに切り替えずに止まります。その場合は、4173 を使っているほかのプログラムを止めてから、もう一度起動してください。

開発中は `npm run dev` でも起動できます（変更がすぐ画面に反映されます。CSP は入りません）。

## テストと確認

| コマンド               | 内容                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| `npm run format:check` | 整形の確認（Prettier）                                                                        |
| `npm run lint`         | リンター（ESLint。指摘が1件でもあれば失敗）                                                   |
| `npm run typecheck`    | 型の検査（TypeScript の strict）                                                              |
| `npm run test:unit`    | 単体テスト（Vitest）                                                                          |
| `npm run coverage`     | 単体テストとカバレッジ（`src` の行カバレッジ 80% 未満で失敗）                                 |
| `npm run build`        | ビルド（`dist/`。CSP の meta 要素を入れる）                                                   |
| `npm run check:dist`   | ビルドの出力の検査（CSP の指定、外部と data: の読み込み先がないこと）                         |
| `npm run e2e`          | ブラウザ操作のテスト（Playwright。Chromium・Firefox・WebKit。先に `npm run build`）           |
| `npm run verify`       | 上のすべてを順に実行（format:check → lint → typecheck → coverage → build → check:dist → e2e） |

ブラウザ操作のテストは、ビルド済みのページを `http://127.0.0.1:4174/` で配信して動かします。
依頼者が使う 4173 とは配信元が違うため、テストが普段の保存データに触れることはありません。

Playwright のブラウザ本体は、初回だけ取得します。

```bash
npx playwright install
```

GitHub Actions（`.github/workflows/app-ci.yml`）では、整形・リンター・型の検査・単体テストとカバレッジ・ビルド・ビルドの出力の検査を動かします。

## データの控え

- 「3 書き出し」の「明細を CSV に保存」で、すべての明細を `budget-entries-YYYYMMDD.csv` として保存できます。
- CSV は UTF-8（BOM 付き）、改行は CRLF、見出しは「日付,区分,カテゴリ,金額,メモ」です。
- CSV には明細だけが含まれ、予算は含まれません。
- この版の CSV には、表計算ソフトでの数式の実行を防ぐ対策がまだありません（U4 で足します）。表計算ソフトで開く控えとしては使わないでください。
- ブラウザのデータ（サイトのデータ）を消すと、保存データも消えます。控えは CSV で取ってください。

## 保存データが読めないとき

保存データが壊れている、または知らない版のときは、アプリはデータを消さずに止まります。
登録と CSV 保存は押せない状態になり、集計の代わりに理由が表示されます。開き直しても保存データはそのまま残ります。

## 置き場所

| 場所              | 中身                                                                         |
| ----------------- | ---------------------------------------------------------------------------- |
| `src/domain/`     | 画面から独立した部品（CategoryCatalog、Ledger、MonthlySummary、CsvExchange） |
| `src/store/`      | DataStore（保存領域の読み書き）                                              |
| `src/ui/`         | 画面部品（AppShell、EntryFormView、ReviewView、ExportView）と見た目          |
| `tests/unit/`     | 単体テスト                                                                   |
| `tests/e2e/`      | ブラウザ操作のテスト                                                         |
| `scripts/`        | ビルドの出力の検査                                                           |
| `csp-policy.json` | ビルドしたページに入れる Content-Security-Policy の指定                      |
