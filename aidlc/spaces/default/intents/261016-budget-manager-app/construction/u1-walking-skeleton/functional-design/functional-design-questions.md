# 機能設計（U1 薄い版）— 質問

U1（`aidlc/spaces/default/intents/261016-budget-manager-app/inception/units-generation/unit-of-work.md`）は、最初に端から端まで通す版です。収支を1件登録すると、その月の集計に反映され、CSV に保存でき、開き直しても残ります。

約束ごと（`aidlc/spaces/default/intents/261016-budget-manager-app/inception/contract-design/contract-summary.md`）、画面の仕様（`inception/refined-mockups/interaction-spec.md`）、ストーリーの受け入れ条件で、多くのことは決まっています。ここでは、契約レビューで B1 に持ち越した点と、U1 の範囲の境目だけを確認します。どの質問も A がおすすめです。

すでに決まっていて、質問しないこと:

- 登録の保存失敗の表示は U1 が作ります（契約レビュー R-10）。登録フォームのお知らせ枠に、読み上げ機能に伝わる形で出し、入力は残します。文言は受け入れ条件 AC7.3.1 に合わせます。
- 初めて開いたときのサンプルデータは U5 で入れます。U1 では、初回は明細0件で始まります。
- 2つのタブの同時保存の隙間（契約レビュー R-03）と、全体のお知らせ枠は U5 で扱います。

## Q1. U1 の部品が、あとの Unit の部品（予算、サンプル投入）を呼ぶ箇所はどうしますか？

契約レビュー R-01 で指摘された点です。月次集計は予算（U3 の Budget）を、起動の処理は初回のサンプル投入（U5）を使います。しかし、どちらも U1 の時点ではまだありません。

A. U1 に「差し込み口」を置く。予算を返す部分は「予算なし」を返す空の実装、初回のサンプル投入は「何もしない」実装を U1 が持つ。あとの U3・U5 は、アプリを組み立てる1か所で本物に差し替える。U1 のほかのコードは書き換えない（おすすめ。依存の向きが Unit の順番と合い、あとの Unit が U1 のコードを書き換えずに済む）
B. あとの U3・U5 が、U1 の呼び出し箇所を直接書き換える
C. 特に希望はない（おすすめでよい）

## Q2. 登録したあと、月次集計の表示を更新するきっかけはどうしますか？
