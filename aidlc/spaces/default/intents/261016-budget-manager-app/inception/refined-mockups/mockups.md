+------------------------------------------------------------+
| 1 登録  収支を登録                                         |
|  [お知らせ枠]                                              |
|  区分 [ 支出 | 収入 ]                                      |

+------------------------------------------------------------+
| 2 確認  月次集計                                           |

ラフ案A から変えた点:

- 予算は月次集計の表の中で直接入力する（要件分析 Q6）。表の下に「予算を保存」「前の月の予算をコピー」を置く。
- 明細の一覧を「2 確認」の中へ移した。月を切り替えると、集計と一覧が同時に変わる。
- 確認は、操作したボタンのすぐ下に枠で出す（このステージの Q1）。画面中央のダイアログは使わない。
- CSV の説明に「予算は含まれない」「形式」を明記した（ストーリー AC5.1.5）。

## このステージで決めた細部

- CSV のメモに改行がある行は取り込まず、「N行目: メモに改行は使えません」と表示する（Q2。ストーリーのレビュー指摘 R-02）。
- メモの前後の空白は、画面での登録時も CSV の取り込み時も除く。これで出力 → 取り込みで必ず同じになる（Q3。ストーリーのレビュー指摘 R-04）。
- 使いやすさとアクセシビリティは、axe で重大な違反 0 件、キーボードだけでの操作確認、初めてでも 5 分以内に一連の操作を完了、で確かめる（Q4。ストーリー US8.1 の仮定を確定）。
- 画面の幅は 1024px 以上が主。768〜1023px では2列の部分（日付と金額、収入・支出・差額）を1列にして崩れないようにする（Q5）。

## ストーリーのレビューで残った点への対応

| 指摘 | 対応 |
|------|------|
| R-01 往復の確認が薄い版に入らない取り込みに依存 | 薄い版での CSV 出力の確認は「出力ファイルの中身（引用符・カンマ・ダブルクォート）を直接確かめる」とし、出力 → 取り込みの往復の確認は取り込み（US6.1）側で行う。設計段階でテストの置き場所として引き継ぐ |
| R-02 取り込み時の範囲外・存在しない日付・101文字以上・改行 | 範囲外の金額、存在しない日付、101 文字以上のメモ、改行を含むメモの行は、行番号と理由付きで取り込まない（Q2 と、画面入力と同じ基準） |
| R-04 メモの前後の空白 | 常に除く（Q3） |
| R-05 別の月の知らせの内容 | 知らせに日付・カテゴリ・金額も含める（状態 register-other-month） |
| R-06 一覧の各列、NFR2 の個別基準 | 一覧は日付（MM/DD）・区分・カテゴリ・金額（符号・¥・3桁区切り）・メモを表示。NFR2 の個別基準は `accessibility-checklist.md` に記載 |
| R-03 axe と 5 分の仮定 | Q4 で依頼者が確定 |
