# 取り組み概要（Initiative Brief）— 架空データの予算管理Webアプリ

## 意図と課題

- 個人の家計（収支と予算）を把握・管理する手段として使える形を、架空データだけで試す。画面・操作性の試作（PoC）と技術的な検証が目的（意図ステートメント: `aidlc/spaces/default/intents/261016-budget-manager-app/ideation/intent-capture/intent-statement.md`）。
- 利用者・関係者・判断者は依頼者本人1人で、報告の決まりは特にない（関係者マップ: `aidlc/spaces/default/intents/261016-budget-manager-app/ideation/intent-capture/stakeholder-map.md`）。
- 成功基準: 架空データで「収支を登録 → 月次集計を確認 → CSV に出力」の一連の操作を、手順書なしで迷わず完了できる。

## 市場での裏付け

市場調査は今回の進め方に含まれていません。個人用の試作で、市場投入を目的としないためです。

## 実現可能性とリスク

実現可能性の検討は今回の進め方に含まれていません。依頼者が確認したリスクと対策は次のとおりです。

| リスク | 影響 | 対策 |
|--------|------|------|
| 明細を削除できず CSV 取り込みが追加のみのため、同じ CSV の再取り込みで集計が二重になる | 集計が実態とずれる | 要件分析で、取り込み前の注意表示や重複の検出を決める |
| データはブラウザ内にだけあり、ブラウザのデータ消去で失われる | 登録内容が消える | 架空データの試作として許容し、CSV 出力を控えとして案内する |
| 試作をまだブラウザで表示・キーボード操作の確認をしていない | WCAG 2.1 AA 相当を満たせていない可能性 | 詳細モックアップと実装後のテストで確認する |
| デザイン手法の自動チェックが、このワークフローの進め方（アプリ用）を受け付けない | 後の段階でも同じチェックが失敗する | 各段階で中身の確認結果を示し、そのつど依頼者が判断する |

## 範囲の境界

範囲定義書（`aidlc/spaces/default/intents/261016-budget-manager-app/ideation/scope-definition/scope-document.md`）と意図バックログ（`aidlc/spaces/default/intents/261016-budget-manager-app/ideation/scope-definition/intent-backlog.md`）の要点です。

- 含める: 収支の登録と一覧（修正・削除なし）、用意済みカテゴリ、月ごとのカテゴリ別予算、月次集計（収入・支出・差額、カテゴリ別の予算・実績・残額）、明細 CSV の出力と追加取り込み、架空のサンプルデータを最初から入れる、ブラウザ内でのデータ保持。
- 含めない: 実口座連携・外部送信、利用者認証・複数利用者、明細の修正・削除、絞り込み・検索、カテゴリの編集、予算や集計の CSV 入出力、全データの一括消去。
- 作業のまとまりと順番（価値優先）: PU-1 登録と一覧 → PU-2 月次集計 → PU-3 CSV 出力 → PU-4 予算と予算比較 → PU-5 CSV 取り込み。期限はない。

## 画面のイメージ

ラフワイヤーフレーム（`aidlc/spaces/default/intents/261016-budget-manager-app/ideation/rough-mockups/wireframes.md`）で3案を比較しました。次の段階は **案A（縦積みのステップ順）** を土台にします。

```
+-----------------------------------------------+
| 予算管理   架空データで試す家計簿             |
+-----------------------------------------------+
| 1 登録   収支を登録（区分・日付・金額・       |
|          カテゴリ・メモ） [ 登録する ]        |
+-----------------------------------------------+
| 2 確認   月次集計 < 2026年10月 >              |
|          収入 / 支出 / 差額                   |
|          カテゴリ別 予算 / 実績 / 残額        |
|          10月の明細                           |
+-----------------------------------------------+
| 3 書き出し  [ CSV に保存 ] [ CSV を取り込む ] |
+-----------------------------------------------+
```

見た目の方向は、パソコン中心、落ち着いて安心できる印象、ライトテーマのみ、派手な色や動きなし、WCAG 2.1 AA 相当です。

## 体制

依頼者本人1人の取り組みのため、チームの編成は行いません。並列で作業する場合は、担当ごとに別ブランチと worktree を使い、統合後に再テストします。作業の記録は、各段階の承認ごとに作業ブランチへコミット・push します。

## 次の段階へ引き継ぐ点

- ラフ案のレビューで残った点: 予算設定の画面（入力欄・保存・入力誤り）、CSV の重複取り込み前の注意表示。要件分析で振る舞いを決め、詳細モックアップで画面として描く。
- 範囲定義書で要件分析に回した点: 重複取り込みの扱い、用意していないカテゴリを含む CSV の扱い、予算未設定時の表示。
- 案C のスキップリンク（「本文へ移動」）が登録フォームを飛び越える不一致。土台は案A のため影響は小さいが、詳細モックアップでスキップリンクの移動先を確認する。

## 判定の推奨

**Go（次の「要件・設計」の段階へ進む）** を推奨します。目的・範囲・画面の方向が依頼者に確認されており、残った点はすべて次の段階で扱う場所が決まっているためです。最終判断は承認ゲートで依頼者が行います。
