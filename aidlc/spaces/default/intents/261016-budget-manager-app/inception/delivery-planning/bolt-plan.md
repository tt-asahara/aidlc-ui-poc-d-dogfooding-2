Bolt とは、作業の一部を設計から実装・テストまで1回通し、ブラウザで動くものができたところで区切る単位です。この計画では、1つの Bolt に1つの Unit を入れます（Q3）。Bolt は全部で6つで、1つずつ順に進めます（Q4）。

## 進め方の共通の決まり

- **順番**: B1（U1）→ B2（U5）→ B3（U2）→ B4（U3）→ B5（U4）→ B6（U6）（Q1）。Unit の依存関係（U5 は U1 に、U2・U3・U4 は U5 に、U6 は U2・U3・U4 に依存）と同じ順番です。
- **各 Bolt で通る工程**: 機能設計 → NFR 要件 → NFR 設計 → インフラ設計 → コード生成 → ビルドとテスト。Unit ごとに1つずつ通します（unit-major、serial）。
- **ブランチ**: 作業ブランチ `feat/budget-manager-app` で進めます。並行しないため、担当ごとの worktree は使いません。`main` へは、最後に依頼者の承認を得てから取り込みます（team-practices.md）。
- **コミットと push**: 各工程の承認時、各 Bolt の実装とテストの完了時、不具合の修正時に行います。そのたびに、コミット SHA、push の結果、未完了の事項を報告します。
- **テスト**: 層ごとに実装してから、その層のテストを書いて実行します（test-after）。単体テストは Vitest、ブラウザ操作のテストは Playwright を使います。行カバレッジは 80% 以上を保ちます。
- **確認コマンド**: B1 の最初の確認のときに提案し、承認を得て決めます（Q8）。以降の Bolt でも同じコマンドを使います。
- **完了の確認**: 各 Bolt の終わりに、確認コマンドを実行した結果と、ブラウザで動く様子を依頼者が確認して承認します。

## B1 薄い版（U1 u1-walking-skeleton）— 最初に端から端まで通す版（walking skeleton）

walking skeleton とは、機能は最小限でも、アプリの端から端までが実際につながって動く最初の版のことです。

- **含む Unit**: U1
- **ストーリー**: US1.1、US3.1、US5.1、US7.2
- **確かめる仕組みのつながり**:
  - 画面（AppShell・EntryFormView・ReviewView・ExportView）
  - 明細の扱い（Ledger・CategoryCatalog）
  - 集計（MonthlySummary）
  - CSV の出力（CsvExchange）
  - ブラウザ内の保存（DataStore）
  - これらがつながること
- **完了の条件**:
  - 収支を1件登録すると、その月の収入・支出・差額に反映される。
  - その月の明細を CSV ファイルに保存できる。
  - ブラウザを開き直しても、登録した明細が残っている。
  - 保存データは最初から、明細・予算・版番号・通し番号をすべて持つ形にする（契約設計の C2）。
  - 失敗は結果の値で返す（C1）。
  - 登録の保存に失敗したときの表示（保存できない、別のタブで変更あり、保存データが読み込めない）を、この Bolt で作る（契約レビュー R-10）。
  - 上の流れを Playwright で通しで確かめるテストがあり、単体テストを含めて行カバレッジ 80% 以上。Prettier と ESLint の指摘がない。
  - 依頼者が承認した確認コマンドで、最初から最後まで動くことを示す。
- **この Bolt で確かめたいこと**: 選んだ部品の境目（ADR-001〜006）と「全体をまとめて保存する」形で、登録 → 集計 → CSV 出力 → 再読み込みが本当につながるか。つながらなければ、残りの Bolt に進む前に設計を直す。
- **見せるもの**: ブラウザで1件登録し、集計に出て、CSV ファイルが保存され、開き直しても残っている様子。

## B2 保存の異常・別タブ対応とサンプル（U5 u5-storage-resilience）

- **含む Unit**: U5
- **ストーリー**: US7.1、US7.3（保存の仕組みの側）、US7.4
- **完了の条件**:
  - 版番号と通し番号を照合し、古いタブからの保存を断る（C2、契約設計 Q3）。断ったときは最新を読み直して知らせ、入力は残す。
  - 自分の保存のあとと、別のタブでの変更のあとに、画面へ知らせるきっかけを決めて実装する（契約レビュー R-02）。
  - 読み込みと書き込みの間の隙間（契約レビュー R-03）は、排他の仕組みで閉じるか、残るリスクとして記録するかを、この Bolt の設計で決める。
  - 壊れたデータや知らない版を見つけたら、消さずに保存を止めて知らせる（契約設計 Q2）。
  - 初めて開いたときに、直近3か月分の架空の明細と予算を1回の保存で入れる（全部か無か）。
  - 2つのタブを使う Playwright のテストで、片方の古い保存が断られ、明細が消えないことを確かめる。
  - 行カバレッジ 80% 以上。Prettier と ESLint の指摘がない。
- **この Bolt で確かめたいこと**: いちばん心配な保存まわり（Q6）で、明細が消えたり食い違ったりしないこと。U2〜U4 が使う保存の結果と状態の形が、この時点で最終形として固まること。
- **見せるもの**: 2つのタブで同時に登録し、古いタブの保存が断られて知らせが出る様子。初回起動でサンプルが入る様子。

## B3 登録の検証と明細一覧（U2 u2-entry-and-ledger）

- **含む Unit**: U2
- **ストーリー**: US1.2、US1.3、US2.1
- **完了の条件**:
  - 金額・日付・カテゴリ・メモの規則（要件 FR1、ストーリーの差分、詳細モックアップ Q3）で、欄ごとに誤りを示す。
  - 二重送信を防ぐ。
  - 別の月の日付で登録したら、表示をその月に切り替える。
  - 月の明細を新しい順に一覧で表示し、空の月には案内を出す。
  - 規則の判定は画面から独立させ、B5（取り込み）でも使える形にする。
  - B2 のサンプル投入の全件が、この Bolt で入れた規則を通ることをテストで確かめる（契約レビュー R-11）。
  - 行カバレッジ 80% 以上。Prettier と ESLint の指摘がない。
- **この Bolt で確かめたいこと**: 規則の判定を1か所（Ledger）に置く形で、画面と取り込みの両方から同じ判定が使えること。
- **見せるもの**: 誤った入力で欄ごとの誤りが出る様子。別の月で登録すると表示が切り替わる様子。新しい順の一覧。

## B4 月別予算と予算比較（U3 u3-budget）

- **含む Unit**: U3
- **ストーリー**: US3.2、US4.1、US4.2
- **完了の条件**:
  - 支出カテゴリごとの予算（0〜9,999,999。空欄は未設定）を入力し、1か月分まとめて検証して保存する。
  - 前の月の予算を写せる。上書きになるときは確認する。
  - 集計に、予算・実績・残額・超過・未設定を表示する。
  - 予算の保存に失敗したときの表示と、保存データが読み込めないときに保存を止める扱いを作る（契約設計 Q4）。
  - 行カバレッジ 80% 以上。Prettier と ESLint の指摘がない。
- **この Bolt で確かめたいこと**: 集計（MonthlySummary）に予算の列を足しても、B1 の集計の結果が変わらないこと。
- **見せるもの**: 予算を入れて保存し、超過と未設定が表示される様子。前月コピー。

## B5 CSV の数式対策と取り込み（U4 u4-csv-import）

- **含む Unit**: U4
- **ストーリー**: US5.2、US6.1、US6.2、US6.3
- **完了の条件**:
  - 数式のように見えるメモを、安全な形で出力する（要件 FR6.4、ストーリーの差分）。
  - CSV の取り込みでは、次の確認を行う。取り込みは全部か無かで行う。
    - ファイル全体の確認
    - 行ごとの検証（B3 の規則を使う）
    - 重複の確認
    - 結果の表示
  - 取り込みの途中状態は ExportView が持ち、やめたら捨てる（契約設計 C7）。
  - 取り込みの保存に失敗したときの表示と、保存データが読み込めないときに取り込みを止める扱いを作る。
  - 出力したファイルをそのまま取り込み直せることを、テストで確かめる。
  - 行カバレッジ 80% 以上。Prettier と ESLint の指摘がない。
- **この Bolt で確かめたいこと**: 信用しない入力（ADR-003）として扱っても、正しいファイルは問題なく取り込め、誤りのある行は理由とともに示されること。
- **見せるもの**: 誤りのある行を含むファイルの取り込み結果。重複の確認。出力 → 取り込みの往復。

## B6 アクセシビリティの仕上げ（U6 u6-accessibility）

- **含む Unit**: U6
- **ストーリー**: US8.1
- **完了の条件**:
  - 次の操作がキーボードだけで終えられる: 登録 → 集計 → 予算 → CSV 出力 → 取り込み。
  - 本文へ移動できる。
  - 読み上げの確認をする。
  - axe の検査で重大な指摘がない（要件 NFR2・NFR8、`accessibility-checklist.md`）。
  - 見つかった点を直したあとも、それまでの全テストが通る。
  - 行カバレッジ 80% 以上。Prettier と ESLint の指摘がない。
- **この Bolt で確かめたいこと**: 各 Bolt で作り込んだ基本のアクセシビリティが、通しで操作しても崩れていないこと。
- **見せるもの**: マウスを使わずに一連の操作を終える様子。axe の検査結果。

## Bolt の外で残ること

- 性能（NFR1）、外部通信なし（NFR3）、対応ブラウザ（NFR6）は、各 Bolt の NFR 要件の工程で確かめ方を決めます。保守性・テスト（NFR7）は、各 Bolt のビルドとテストで確かめます。
- `main` への取り込みは、B6 のあとに依頼者の承認を得て行います。取り込む前に、GitHub Actions で Prettier と ESLint を通します（team-practices.md）。その設定は後の工程で用意します。
