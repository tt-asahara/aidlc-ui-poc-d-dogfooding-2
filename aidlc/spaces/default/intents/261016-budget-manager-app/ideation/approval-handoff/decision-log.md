# 意思決定の記録 — アイデア段階

すべての決定者は依頼者本人です。出典は各段階の質問ファイル（`*-questions.md`）と承認ゲートです。

## 進め方の決定

| No. | 決定 | 理由・根拠 | 出典 |
|-----|------|------------|------|
| D-01 | 進め方は `ui-poc-application`（画面のあるアプリ向け、20段階） | 依頼が Web アプリで、画面の試作を伴うため | 開始時の進め方の確認 |
| D-02 | 質問への回答は対話形式（Guide me）で行う | 依頼者の選択 | intent-capture の回答方法 |
| D-03 | チーム編成の段階は行わない | 依頼者・利用者・判断者が同じ1人のため | team-formation（実施なし） |
| D-04 | GitHub への記録: 作業ブランチ `feat/budget-manager-app` で、各段階の承認ごとにコミット・push する。main へは直接変更しない | 依頼者の指示 | 会話での指示 |
| D-05 | デザイン手法の自動チェックの不合格を、ラフモックアップで依頼者の判断により上書きした | チェックが比較実験用の進め方しか受け付けず、中身の確認は合格していたため | rough-mockups の承認前の判断 |

## 意図の把握（intent-capture）

| No. | 決定 | 出典 |
|-----|------|------|
| D-06 | 目的は、個人の家計（収支と予算）を把握・管理する手段を試すこと | intent-capture Q1 |
| D-07 | 利用者・関係者・判断者は依頼者本人のみ。報告の決まりはない | intent-capture Q2, Q5, Q6, Q7 |
| D-08 | 成功基準は「登録 → 月次集計を確認 → CSV に出力」を迷わず完了できること | intent-capture Q3 |
| D-09 | きっかけは画面・操作性の PoC と技術検証 | intent-capture Q4 |
| D-10 | 最初のバージョンから外す: 利用者認証・複数利用者でのデータ共有。実口座連携・外部送信は依頼時点で対象外 | intent-capture Q8、依頼文 |

## 範囲の定義（scope-definition）

| No. | 決定 | 出典 |
|-----|------|------|
| D-11 | 収支登録は登録と一覧のみ（修正・削除なし） | scope-definition Q1 |
| D-12 | カテゴリは用意済みのものだけを使う | scope-definition Q2 |
| D-13 | 予算は月ごとにカテゴリ別で設定する | scope-definition Q3 |
| D-14 | 月次集計は収入・支出・差額と、カテゴリ別の予算・実績・残額を表示する | scope-definition Q4, Q10 |
| D-15 | CSV は明細の出力と取り込みのみ。取り込みは既存の明細への追加 | scope-definition Q5, Q12 |
| D-16 | 架空のサンプルデータを最初から入れる | scope-definition Q6 |
| D-17 | 同じパソコン・同じブラウザで開き直してもデータが残る | scope-definition Q7 |
| D-18 | 誤登録やサンプルデータを消す手段はなくてよい（試作として許容） | scope-definition Q11 |
| D-19 | 作る順番は価値優先。期限はない | scope-definition Q8, Q9 |
