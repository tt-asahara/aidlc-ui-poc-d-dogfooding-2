# 性能・利用環境・使いやすさ・保守性の要件 — U1 薄い版

入力:

- 要件 `aidlc/spaces/default/intents/261016-budget-manager-app/inception/requirements-analysis/requirements.md`（NFR1、NFR2、NFR6、NFR7、NFR8）
- 機能の仕様 `aidlc/spaces/default/intents/261016-budget-manager-app/construction/u1-walking-skeleton/functional-design/functional-spec.md`
- このステージの回答 `nfr-requirements-questions.md`（Q1〜Q4、まとめの確認済み）

各要件の ID は、要件の NFR の番号に枝番を付けたものです（例: NFR1.1）。U1 の範囲（登録 → 集計 → CSV 出力 → 保存）に当たるものだけを載せます。取り込みの性能（NFR1 の後半）は U4、通しのアクセシビリティの確認（NFR2）と初めての利用者による確認（NFR8）は U6 で仕上げます。

## 前提となる量

| 項目 | 値 | 出典 |
|------|----|------|
| 保存されている明細の件数 | 3,000 件 | NFR1、仮定 A8 |
| 1か月の明細の件数 | 100 件 | NFR1 |
| 計測に使うパソコン | 一般的な事務用パソコン | 仮定 A8 |
| 利用者の数 | 1人（同時に開くタブは最大2つ） | 意図ステートメント、US7.4 |

利用者は1人で、データはブラウザの中だけにあります。そのため、利用者数やデータ量の増加に合わせて処理能力を広げる検討（スケーラビリティ）は対象外です。

## 性能（NFR1）

| ID | 要件 | 合否の基準 | 確かめ方 |
|----|------|------------|----------|
| NFR1.1 | 明細 3,000 件・1か月 100 件のデータで、「登録する」を押してから、集計が新しい値に変わるまで 1 秒以内 | 計測値が 1 秒以内 | Playwright で 3,000 件の保存データを置いてから登録し、ボタン操作から集計の表示が変わるまでの時間を測る |
| NFR1.2 | 同じデータで、「前の月」「次の月」を押してから集計が変わるまで 1 秒以内 | 計測値が 1 秒以内 | NFR1.1 と同じ方法で測る |
| NFR1.3 | 同じデータで、起動してから登録フォームと集計が操作できるようになるまで 1 秒以内（目安） | 計測値が 1 秒以内 | Playwright でページを開いてから、集計の表示が出るまでの時間を測る |
| NFR1.4 | 3,000 件の CSV 出力の組み立てが 1 秒以内 | 計測値が 1 秒以内 | 単体テストで exportAll の時間を測る |
| NFR1.5 | 月次集計の計算（3,000 件から1か月分を集計）が 100 ミリ秒以内（目安） | 計測値が 100 ミリ秒以内 | 単体テストで summarize の時間を測る。NFR1.1・NFR1.2 の 1 秒に余裕を残すための内訳 |
| NFR1.6 | 金額の計算は円の整数で行い、最大値（9,999,999 円 × 300 件 = 2,999,999,700 円）でも誤差がない | 合計が ¥2,999,999,700 と表示される | 単体テスト（AC3.1.6） |

時間の計測は、ばらつきを減らすため3回測った中央値で判定します。テストを動かすパソコンが遅くて基準を超えた場合は、失敗として扱います。ただし、記録を残して原因を確かめてから判断します。

## 利用環境（NFR6）

| ID | 要件 | 合否の基準 | 確かめ方 |
|----|------|------------|----------|
| NFR6.1 | パソコンの最新版の Chrome・Edge・Firefox・Safari で、登録 → 集計 → CSV 出力ができる | 4つで操作が完了する | Playwright で Chromium・Firefox・WebKit の3種類の描画の仕組みで同じテストを動かす（Chrome と Edge は Chromium、Safari は WebKit で代える） |
| NFR6.2 | 画面幅 1024px 以上と、768〜1023px の両方で崩れない | 2列の部分が 768〜1023px で1列になる | Playwright で 1280px と 800px の2つの幅で表示を確かめる |
| NFR6.3 | 200% に拡大しても操作できる | 横方向のスクロールなしで登録できる | U1 では 200% 拡大での登録をブラウザ操作のテストで1回確かめる。通しの確認は U6 |

## 使いやすさとアクセシビリティ（NFR2、NFR8）

| ID | 要件 | 合否の基準 | 確かめ方 |
|----|------|------------|----------|
| NFR2.1 | U1 の画面の基本のアクセシビリティを作り込む。次のものが対象 | `frontend-components.md` のアクセシビリティの項目がすべて実装されている | Testing Library と Playwright のテストで、名前・役割・読み上げの指定を確かめる |
| NFR2.2 | U1 の画面の状態で、axe の検査に重大（critical・serious）な違反がない。対象の状態は次のとおり | 違反 0 件 | Playwright と axe で検査する。通しの検査は U6 |
| NFR2.3 | キーボードだけで、登録 → 月の切り替え → CSV 出力ができる | マウスを使わずに完了する | Playwright でキーボード操作だけのテストを動かす |
| NFR8.1 | 成功基準の3つの操作が、上から順の1画面で手順書なしに分かる | 「1 登録」「2 確認」「3 書き出し」の見出しが順に並ぶ | 画面の構成のテスト。依頼者が初めて使う確認（5 分以内）は U6 |

NFR2.1 で作り込むもの:

- 見える見出し
- 本文へ移動
- 操作位置の枠線
- お知らせの読み上げ
- 表の見出し
- コントラスト

NFR2.2 で検査する状態:

- 初期
- 登録成功
- 入力の誤り
- 保存失敗
- 保存データが読めない
