## 意図の分析

- 依頼者本人が1人で、個人の家計（収支と予算）を把握・管理する手段を、架空データだけを使って試す（意図ステートメント）。
- 目的は画面・操作性の試作（PoC）と技術検証であり、実運用ではない（意図ステートメント）。
- 成功基準: 「収支を登録 → 月次集計を確認 → CSV に出力」の一連の操作を、手順書なしで迷わず完了できる（意図ステートメント）。
- 種別: 新規開発。規模: 単一のブラウザアプリ（複数の画面部品）。複雑さ: 標準（業務ロジックは集計・予算比較・CSV の変換と検証）。

## 機能要件

### FR1 収支の登録

| ID | 要件 | 合否の基準 | 出典 |
|----|------|------------|------|
| FR1.1 | 明細は「区分（収入／支出）」「日付」「金額」「カテゴリ」「メモ（任意）」を入力して登録できる | 5項目を入力して「登録する」を押すと、明細が1件増え、一覧と月次集計に反映される | 範囲定義書、ラフ案A |
| FR1.2 | 金額は 1 円以上 9,999,999 円以下の整数のみ受け付ける | 0、負の数、小数、10,000,000 以上、数字以外を入れて登録すると登録されず、金額欄の下に直し方（例:「金額は 1〜9,999,999 の整数で入力してください。例: 1280」）が表示され、入力した値は残る | Q1 |
| FR1.3 | 日付は存在する日付であれば、過去・未来を問わず受け付ける。未入力は受け付けない | 2026-02-30 のような存在しない日付や空欄では登録されず、日付欄に理由が表示される。2000-01-01 や 2030-12-31 は登録できる | Q2 |
| FR1.4 | カテゴリは、選んだ区分に対応する用意済みカテゴリ（FR3）からのみ選べる | 区分を「収入」にすると収入カテゴリだけが選択肢に出る。区分を切り替えると、合わないカテゴリの選択は解除される | 範囲定義書（用意済みカテゴリのみ） |
| FR1.5 | メモは任意で、最大 100 文字まで入力できる。入力された文字は、そのまま文字として表示する | 101 文字目は入力できないか、登録時に理由が表示される。`<b>` などを入力しても、画面上で書式として解釈されず文字のまま表示される | コーナー確認（長い文字・記号）、仮定 A1 |
| FR1.6 | 登録できたら、追加した内容（日付・カテゴリ・金額）をフォームの近くに知らせる | 登録直後に「登録しました」と追加した内容が、読み上げ機能にも伝わる形で表示される | ラフ UI 契約 AC-R03 |
| FR1.7 | 「登録する」を素早く2回押しても、明細は1件だけ増える | 連続2回の操作で明細が2件にならない | コーナー確認（二重送信） |
| FR1.8 | 登録した明細の修正・削除はできない | 一覧に修正・削除の操作がない | 範囲定義書（Q1、Q11） |

### FR4 月次集計

| ID | 要件 | 合否の基準 | 出典 |
|----|------|------------|------|
| FR4.1 | 月を前後に切り替えられ、開いたときは今日を含む月を表示する | 「前の月」「次の月」で月が1か月ずつ変わる。年をまたいでも正しく切り替わる（2026年1月の前は2025年12月） | 範囲定義書、ラフ UI 契約 |
| FR4.2 | 選んだ月の収入合計・支出合計・差額（収入合計 − 支出合計）を表示する | ラフ UI 契約の例（収入 ¥280,000、支出 ¥119,220）で差額 ¥160,780 と表示される。差額が負のときは「−」を付けて表示する | 範囲定義書（Q4）、AC-R07 |
| FR4.3 | 支出カテゴリごとに、その月の予算・実績・残額（予算 − 実績）を表示する | 各支出カテゴリの行に3つの値が表示される | 範囲定義書（Q10）、AC-R07 |
| FR4.4 | 実績が予算を超えたカテゴリは、色に加えて「超過 ¥3,900」のように文字で示す | 色の見分けがつかなくても、文字で超過が分かる | ラフ UI 契約 AC-R09、NFR2 |
| FR4.5 | 予算を設定していないカテゴリは、予算欄に「未設定」と表示し、残額は表示せず、超過とも扱わない | 予算未設定のカテゴリに実績があっても超過表示にならない | Q5、AC-R08 |
| FR4.6 | 支出カテゴリ別の実績の合計は、支出合計と必ず一致する | 任意のデータで、カテゴリ別実績の和 ＝ 支出合計 | コーナー確認（グループ合計） |
| FR4.7 | 金額の計算は円の整数で行い、端数は発生させない | 9,999,999 円を 300 件登録しても合計が正しく表示される | コーナー確認（お金） |

### FR5 月ごとのカテゴリ別予算

| ID | 要件 | 合否の基準 | 出典 |
|----|------|------------|------|
| FR5.1 | 月次集計の表の予算欄に、月ごと・支出カテゴリごとの予算額を直接入力して保存できる | 予算欄に金額を入れて保存すると、その月のその行の予算・残額が更新される。ほかの月の予算は変わらない | Q6、範囲定義書（Q3） |
| FR5.2 | 予算額は 0 円以上 9,999,999 円以下の整数とする。空欄は「未設定」を意味する | 負の数・小数・範囲外は保存されず、その欄に直し方が表示される。空欄で保存すると「未設定」に戻る | Q1 に準拠、仮定 A3 |
| FR5.3 | 「前の月の予算をコピー」で、前の月に設定されている予算を、選んでいる月へ写せる。写し先にすでに予算がある場合は、上書きしてよいかを確認する | 前の月の予算がそのまま写る。既存の予算がある月では、確認でやめると何も変わらない | Q6 |
| FR5.4 | 前の月に予算が1つもないとき、コピーの操作は理由を表示して何もしない | 「前の月の予算がありません」と表示され、データは変わらない | コーナー確認（空の集合） |

### FR6 CSV への出力

| ID | 要件 | 合否の基準 | 出典 |
|----|------|------------|------|
| FR6.1 | 保存されているすべての明細を、日付の古い順で1つの CSV ファイルとして保存できる | 出力ファイルの行数 ＝ 明細の件数 ＋ 見出し1行 | 範囲定義書（Q5）、仮定 A4 |
| FR6.2 | 文字コードは UTF-8（BOM 付き）、改行は CRLF、見出しは「日付,区分,カテゴリ,金額,メモ」とする。日付は YYYY-MM-DD、金額は区切りなしの整数で出力する | Excel で開いて文字化けしない。見出しと値の形式が一致する | Q7 |
| FR6.3 | カンマ・ダブルクォート・改行を含むメモは、ダブルクォートで囲み、中のダブルクォートは2つ重ねて出力する | そのような明細を出力して取り込み直すと、メモが元と同じになる | コーナー確認（区切り文字を含む値） |
| FR6.4 | メモが「=」「+」「-」「@」で始まるときは、表計算ソフトで数式として実行されないよう、先頭に「'」を付けて出力する。取り込み時に「'」に続く文字がこれらの記号であれば、「'」を外して元に戻す | 「=1+1」というメモが表計算ソフトで計算されない。取り込み直すと「=1+1」に戻る | コーナー確認（表計算の数式）、仮定 A5 |
| FR6.5 | ファイル名は `budget-entries-YYYYMMDD.csv`（出力した日）とする | 2026年10月16日に出力すると `budget-entries-20261016.csv` になる | 仮定 A4 |
| FR6.6 | 明細が0件のときは、出力せずに「出力する明細がありません」と知らせる | 0件で出力を押してもファイルができない | コーナー確認（空の入力） |

### FR7 CSV の取り込み

| ID | 要件 | 合否の基準 | 出典 |
|----|------|------------|------|
| FR7.1 | FR6.2 の形式の CSV ファイルを選んで取り込み、正しい行を既存の明細に追加できる。既存の明細は置き換えない | 取り込み後、既存の明細はすべて残り、正しい行の数だけ明細が増える | 範囲定義書（Q5、Q12） |
| FR7.2 | BOM の有無、改行（CRLF／LF）、ダブルクォートで囲まれた値（カンマ・改行を含む）のどれでも読み取れる | BOM なし・LF の CSV も正しく取り込める | Q7、コーナー確認（エンコーディング） |
| FR7.3 | 1行目が「日付,区分,カテゴリ,金額,メモ」でなければ、取り込みを始めずに理由を表示する | 見出しが違うファイルでは何も追加されず、期待する見出しが表示される | コーナー確認（未知の項目） |
| FR7.4 | 各行を FR1.2〜FR1.5 と同じ基準で確かめ、満たさない行は取り込まず、正しい行だけを追加する。取り込めなかった行は、行番号と理由をすべて表示する | 1行だけ金額が不正なファイルでは、その行以外が追加され、「3行目: 金額が数字ではありません」のように表示される | Q4、AC-R11 |
| FR7.5 | 用意していないカテゴリの行は取り込まず、行番号と「カテゴリ『〇〇』は用意されていません」と表示する。区分とカテゴリが合わない行も同様に扱う | 「ペット」というカテゴリの行が取り込まれない | Q4 |
| FR7.6 | 追加する前に、既存の明細と「日付・区分・カテゴリ・金額・メモ」がすべて一致する行の件数を数え、1件以上あれば「既存と同じ明細が N 件あります」と知らせて、「重複分を除いて追加」「すべて追加」「取り込みをやめる」から選ばせる | 同じ CSV を2回取り込むと2回目にこの確認が出る。「取り込みをやめる」を選ぶと何も追加されない | Q3 |
| FR7.7 | 取り込みが終わったら、追加した件数・取り込めなかった件数・重複として除いた件数を表示する | 表示された件数の合計が、ファイルのデータ行数と一致する | AC-R10、コーナー確認（件数の整合） |
| FR7.8 | 見出し以外に行がないファイルは「取り込む明細がありません」と表示し、何も追加しない | 見出しだけの CSV で明細が増えない | コーナー確認（空の入力） |
| FR7.9 | 取り込みは、すべて追加されるか、何も追加されないかのどちらかとする。途中で保存に失敗した場合は、取り込み前の状態に戻し、失敗を知らせる | 保存に失敗しても、一部の行だけが追加された状態にならない | コーナー確認（途中で中断） |
| FR7.10 | 1 回に取り込めるファイルは 5 MB まで、データ行は 10,000 行までとし、超える場合は理由を表示して取り込まない | 6 MB のファイルでは取り込みが始まらず、上限が表示される | コーナー確認（大きすぎる入力）、仮定 A6 |

## 制約

- 実装言語は TypeScript（依頼文）。
- 依頼者のパソコンのブラウザでのみ動かし、公開しない。データはブラウザ内に保持する（team-practices.md、範囲定義書）。
- 架空データのみ。実口座連携と外部送信はしない（依頼文、project.md）。
- 見た目: パソコン中心、落ち着いた印象、ライトテーマのみ、派手な色や動きは使わない。画面構成は案A（縦積みのステップ順）を土台にする（ラフモックアップ、承認と引き継ぎ）。
- 開発の進め方: 実装してからテスト、行カバレッジ 80% 以上、Vitest と Playwright、最初に端から端まで通る薄い版（登録 → 月次集計 → CSV 出力）を作る（team-practices.md）。

## 仮定

| ID | 仮定 | 理由 |
|----|------|------|
| A1 | メモの上限は 100 文字とする | 依頼者に聞いていない細部。一覧の表示が崩れない長さとして設定した。変更を希望されれば直す |
| A2 | 月の区切りと「今日」は、利用しているパソコンの地域の時刻で決める | 1人がローカルで使うため、時差を考える必要がない |
| A3 | 予算は支出カテゴリにだけ設定する。収入カテゴリには設定しない | ラフモックアップの予算表が支出カテゴリのみで、残額・超過は支出にしか意味がないため |
| A4 | CSV 出力は月ごとではなく、すべての明細を対象とする | 出力した CSV を、ブラウザのデータ消去に備えた控えとして使う対策（承認と引き継ぎで確認済みのリスク対策）に合わせるため |
| A5 | 表計算の数式として実行されそうなメモは、先頭に「'」を付けて出力し、取り込み時に戻す | 出力した CSV を表計算ソフトで開く場面の安全のため |
| A6 | 取り込みファイルの上限は 5 MB・10,000 行とする | 想定データ量（全体約 3,000 件）に十分な余裕を持たせつつ、極端に大きいファイルで画面が固まらないようにするため |
| A7 | サンプルデータは、予算超過と予算未設定の表示を確かめられる内容にする | ラフモックアップで確認した状態を、実物でも確かめられるようにするため |
| A8 | 性能の目安は、一般的な事務用パソコンを基準とする | 依頼者のパソコンの性能を聞いていないため |
| A9 | 対応ブラウザはパソコン版の最新の主要4ブラウザとする | 依頼者が使うブラウザを聞いていないため |
| A10 | 1つの CSV ファイルの中で同じ内容の行が複数あっても、すべて別の明細として扱う。重複の確認（FR7.6）は既存の明細とだけ比べる | 同じ日に同じ金額の買い物を2回することは実際にあるため |

## 範囲外

- 実口座との連携、外部へのデータ送信（依頼文）
- 利用者認証、複数利用者でのデータ共有（意図ステートメント）
- 登録済み明細の修正・削除、一覧の絞り込み・検索（範囲定義書）
- カテゴリの追加・名前変更・削除（範囲定義書）
- 予算設定の CSV 入出力、月次集計結果の CSV 出力（範囲定義書）
- 全データの一括消去・サンプルデータへの初期化（範囲定義書）
- 収入カテゴリの予算（仮定 A3）
- スマートフォン向けの専用レイアウト（パソコン中心のため。崩れずに表示できる範囲で対応）
- 公開・配置（team-practices.md）
