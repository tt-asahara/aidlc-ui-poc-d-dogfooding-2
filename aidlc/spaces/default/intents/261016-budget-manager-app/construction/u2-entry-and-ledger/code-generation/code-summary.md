## U1・U5 のテストで変えたところ（確かめる内容は変えていない）

1. **`tests/unit/ui/EntryFormView.test.tsx`（計画どおりの置き換え）:** maxLength=100 を確かめる1行を外しました。代わりに「maxLength がなく、101 文字が 100 文字に切り詰められて知らせが出る」テストを足しました。
   - 理由: maxLength は UTF-16 の単位で数えるため、絵文字を含むと 100 文字より前で止まります。
2. **`tests/unit/ui/ReviewView.test.tsx`:** 必須にした `ledger` を渡すようにしました。また、表が2つになったため、予算の表を名前で選ぶようにしました。
3. **`tests/unit/ui/AppShell.test.tsx`:** 2回目の「登録する」の前に、ボタンが押せる状態になるまで待つ処理を足しました。
   - 理由: 送信の鍵（300 ミリ秒）で、2回目の操作が捨てられていたためです。
4. **`tests/e2e/u1-walking-skeleton/performance.spec.ts` と `tests/e2e/u5-storage-resilience/cross-tab.spec.ts`:** 押す前にボタンが押せる状態になるまで待つ処理を足しました。計測を始める時点は変えていません。理由は 3 と同じです。

## 計画・設計と違う点、判断した点

1. **isRealDate の既存の誤りの修正:** U5 から移した関数は、0000-02-29 を「実在しない」と判定していました。年・月・日をまとめて設定する形に直しました。ほかの日付の結果は変わらず、U5 のテストも変更なしで通っています。
2. **一覧の見出し:** 詳細モックアップにならい、表の上に小見出し「2026年10月の明細」を置きました。caption は仕様どおり「2026年10月の明細（新しい順）」です。
3. **別の月の知らせ:** rules.md の BR2.1 の文にそろえました。モックアップの「表示を2026年9月に切り替えました。」の1文は付けていません。
4. **案内の文と誤りの文:** 誤りがある欄では、案内の文の代わりに誤りの文を出します。
5. **入力中の知らせ:** メモ欄の入力中の切り詰めと改行の知らせには aria-invalid を付けず、aria-describedby だけで結びました。aria-invalid は Ledger.validate の誤りのときだけ付けます。
6. **存在しない日付:** ブラウザの日付の欄には「2026-02-30」を入力できないため、単体テストで確かめました。
7. **改行の貼り付けのテスト:** Firefox で作った事象の中身を読めないため、実際にコピーして貼り付ける方法にしました。3つのブラウザで確かめています。
8. **省略できる受け取るもの:** EntryFormView の `selectedMonth` と `onSelectMonth` は、省略できる形にしました（AppShell は必ず渡す）。

## 日本語入力の手での確認（U2 の完了の条件。インフラ設計レビュー R-01）

手順:

1. リポジトリ直下で `npm --prefix app run build` と `npm --prefix app run serve` を実行し、http://127.0.0.1:4173/ を開く。
2. 「1 登録」のメモ欄で日本語入力をオンにし、確定しないまま 100 文字を超える文字を入力する（例:「あ」を続けて入力）。
3. 変換中に、文字が消えたり壊れたり、途中で切られたりしないことを確かめる。
4. 確定すると値が 100 文字に切り詰められ、欄の下に「メモは 100 文字までです」と出ることを確かめる。
5. （任意）1文字消して 99 文字にすると、欄の下の文が消えることを確かめる。

結果: 依頼者の確認待ち（U2 の確認のときに記録する）。
