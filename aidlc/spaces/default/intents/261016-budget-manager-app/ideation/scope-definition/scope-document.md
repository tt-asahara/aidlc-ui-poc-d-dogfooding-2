# 範囲定義書 — 架空データの予算管理Webアプリ

## 前提

この範囲は、前のステージで確認した意図ステートメント（`aidlc/spaces/default/intents/261016-budget-manager-app/ideation/intent-capture/intent-statement.md`）にもとづきます。

- 目的: 個人の家計（収支と予算）を把握・管理する手段を、架空データだけを使って試す。
- 利用者・判断者: 依頼者本人1人。
- 成功基準: 「収支を登録 → 月次集計を確認 → CSV に出力」の一連の操作を、手順書なしで迷わず完了できる。
- きっかけ: 画面・操作性の試作（PoC）と技術的な検証。

実現可能性と制約の検討ステージは、今回のワークフローの範囲に含まれていません。そのため、参照できる実現可能性評価と制約一覧はありません。

## 範囲に含めるもの（In Scope）

| 機能 | 最初のバージョンでできること | 出典 |
|------|------------------------------|------|
| 収支登録 | 収入・支出の明細を登録し、一覧で確認できる | Q1 |
| カテゴリ | あらかじめ用意したカテゴリ（収入・支出の分類）から選ぶ | Q2 |
| カテゴリ別予算 | 月ごとに、カテゴリ別の予算額を設定できる | Q3 |
| 月次集計 | 指定した月の収入合計・支出合計・差額を表示する | Q4 |
| 月次集計（予算比較） | 同じ画面で、カテゴリ別の予算・実績・残額を表示する | Q10 |
| CSV 出力 | 収支明細を CSV ファイルに出力できる | Q5 |
| CSV 取り込み | 収支明細の CSV ファイルを取り込み、既存の明細に追加できる | Q5, Q12 |
| 架空のサンプルデータ | 初めて開いたときから、架空のサンプルデータが入っている | Q6 |
| データの保持 | 同じパソコン・同じブラウザで開き直しても、登録したデータが残っている | Q7 |

## 範囲に含めないもの（Out of Scope）

| 項目 | 理由・出典 |
|------|------------|
| 実口座との連携、外部へのデータ送信 | ご依頼の時点で対象外 |
| ログインなどの利用者認証、複数利用者でのデータ共有 | 意図の把握で最初のバージョンから外すと確認済み |
| 登録済み明細の修正・削除 | 「登録と一覧のみ」と確認済み（Q1）。誤登録やサンプルデータを消す手段がないことも、試作として許容すると確認済み（Q11） |
| 一覧の絞り込み・検索 | 「登録と一覧のみ」と確認済み（Q1） |
| カテゴリの追加・名前変更・削除 | 「用意済みカテゴリだけを使う」と確認済み（Q2） |
| 予算設定の CSV 入出力、月次集計結果の CSV 出力 | 「収支明細の入出力のみ」と確認済み（Q5） |
| 全データの一括消去・サンプルデータへの初期化 | Q11 で選ばれなかった。必要になった場合は範囲の変更として扱う |

## 最小限の価値ある範囲（Minimum Viable Scope）

成功基準の流れ「登録 → 月次集計を確認 → CSV に出力」が最初から最後までつながることを、最小限の範囲とします。範囲に含めるものは期限がなく（Q9）、すべて最初のバージョンに入れます。作る順番は、この流れが最初につながる順にします（価値優先、Q8）。

## 後続の段階で詰める点

範囲の判断としては確定しています。ただし、次の点は要件分析で具体的な振る舞いを決める必要があります。

- 明細を削除できず、CSV 取り込みは追加だけなので、同じ CSV を2回取り込んだり、出力した CSV を取り込み直したりすると、同じ明細が重複して集計が二重になります。重複の扱い（取り込み前の注意表示、重複の検出など）を要件分析で決めます。
- カテゴリは固定なので、取り込む CSV に用意していないカテゴリが含まれていた場合の扱いを要件分析で決めます。
- 予算を設定していない月やカテゴリについて、集計での表示（「未設定」と表示するか、0 として扱うか）を要件分析で決めます。

## 期限

特定の機能にも全体にも期限はありません（Q9）。
